# Визитка — visiooo.ru

Сервис электронных визиток на Django и PostgreSQL. Отдельные фото фона, аватара и шапки, социальные сети, три оформления, QR, сохранение контакта, привязка физических QR/NFC носителей и собственных доменов. Подписка: **199 ₽ в месяц / 1490 ₽ в год**.

В репозитории находятся код, миграции и демонстрационные изображения. Пользовательские фотографии, база данных и секреты исключены из Git.

## Сервер: установка и обновление через GitHub

Подробная инструкция: [ops/SERVER.md](ops/SERVER.md). Требуются Linux, Git, Python 3, Docker Engine с Compose v2 и Nginx. На сервере:

```bash
git clone https://github.com/Miha1990/visiooo.git /opt/visiooo
cd /opt/visiooo
python3 ops/init_production_env.py
nano app/.env
bash ops/deploy.sh
```

После первого запуска настроить Nginx и HTTPS по инструкции. Для следующих обновлений:

```bash
cd /opt/visiooo
bash ops/deploy.sh
```

Сценарий выполняет `git pull --ff-only`, собирает приложение, сохраняет резервную копию базы, применяет миграции и перезапускает приложение с проверкой готовности. База и фотографии сохраняются в отдельных томах Docker; `app/.env` остаётся на сервере. Локальные учётные записи и фотографии автоматически не переносятся.

## Выпуск физических карт для клиентов

Администратор с правом `cards.add_physicalcard` выпускает заготовки прямо в админ-панели: кнопка «Выпустить карты NFC / QR» или `/admin/cards/physicalcard/add/`. Можно выпустить до 100 ссылок за раз, скачать список CSV и QR PNG каждой карты. Также доступна страница `/control/physical-cards` из раздела физических визиток.

Для каждой физической карты записывается её отдельная ссылка `/p/<идентификатор>` как URL-запись NFC; в QR на этой же карте должна быть та же ссылка. До активации ссылка открывает страницу входа и выбора электронной визитки. После явного подтверждения карта закрепляется за аккаунтом клиента, а постоянная ссылка начинает открывать его опубликованную визитку. iPhone может пройти этот сценарий через обычную камеру и QR, без записи NFC из браузера. Перепривязать активированную карту может только её владелец из личного кабинета.

Обновление через `ops/deploy.sh` применяет миграцию `cards/0011_physical_card_activation`. Ранее созданные привязки продолжают работать.

## Локальная разработка

Windows: `powershell -ExecutionPolicy Bypass -File ops/start.ps1`; для SQLite добавить `-SQLite`. Подробности: [app/README.md](app/README.md). `compose.yaml` предназначен для локальной базы, `compose.production.yaml` — для сервера.

Проверки выполняются локально перед отправкой изменений. GitHub используется для хранения кода; автоматические тесты и сборки в GitHub отключены.

## Необязательная аналитика

Необязательная Яндекс Метрика, отдельное согласие, отказ и отзыв: [ops/ANALYTICS.md](ops/ANALYTICS.md). До указания номера счётчика в `YANDEX_METRIKA_ID` аналитика полностью выключена. Настроенный счётчик работает только после отдельного разрешения посетителя на рекламных страницах сервиса.

## Поиск и предпросмотр ссылок

`/robots.txt` ссылается на `/sitemap.xml`, где перечислены только открытые информационные страницы сервиса. Адреса формируются из `PUBLIC_BASE_URL`. Личный кабинет, регистрация, платежи, примеры и пользовательские визитки не предназначены для индексации; визитки сохраняют `noindex,nofollow`.

Страницы содержат описание, канонический адрес и метаданные Open Graph/Twitter Card. Общая обложка — `app/static/brand/share-cover.png` (1200×630), воспроизводится на Windows командой `python ops/build_share_cover.py`. У опубликованных визиток используются имя, должность и фото из опубликованной версии; фото выдаётся через существующий маршрут с проверкой публичного доступа. На собственных доменах канонический адрес остаётся на домене владельца, карта сайта не перечисляет другие визитки. `/favicon.ico` напрямую отдаёт файл значка с кодом 200.

## Перед запуском продаж

Полноценная почта на сервере, веб-почта и отправка служебных писем: [ops/MAIL.md](ops/MAIL.md). Почтовый стек устанавливается отдельно после настройки DNS и сертификата, обычное обновление сайта его не запускает.

Интеграция ЮКассы реализована, но платежи выключены до настройки магазина и проверки оплаты. Заполнить SMTP, адрес оператора и сведения о хостинге/почте, проверить документы и порядок чеков НПД: [ops/PAYMENTS_AND_LEGAL.md](ops/PAYMENTS_AND_LEGAL.md). Собственные домены требуют отдельного обработчика: [ops/DOMAINS.md](ops/DOMAINS.md). DNS и HTTPS проверяются после настройки сервера: [ops/VISIOOO_DOMAIN.md](ops/VISIOOO_DOMAIN.md).

Исходные проектные материалы: [продукт](01-product.md), [архитектура](02-architecture.md), [план](03-delivery.md). Текущее поведение отражено в коде и инструкциях эксплуатации.
