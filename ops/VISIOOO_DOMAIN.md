# Основной домен: visiooo.ru

Утверждён основной адрес сервиса **https://visiooo.ru**. Это адрес всего сервиса, личного кабинета, юридических документов и оплаты; он не добавляется в реестр пользовательских доменов отдельной визитки.

В локальном `app/.env` изменены `PUBLIC_BASE_URL` и `ALLOWED_HOSTS`. Локальный предпросмотр продолжает работать по `http://127.0.0.1:8000/`. Новые ссылки в QR, бесконтактных носителях, письмах подтверждения и возврате из ЮКассы используют основной домен. Они откроются с других устройств после реального подключения DNS и HTTPS. При переносе сохраняются база данных, постоянные идентификаторы визиток/носителей и private-media.

## Подключение у регистратора

Владелец подтвердил регистрацию домена у **REG.RU** и указал сервер **31.192.110.184**. Этот IPv4 добавлен в `DOMAIN_IPV4` локальной конфигурации и производственного шаблона. 22.11.2026 владелец сообщил, что самостоятельно добавил IP в REG.RU. Независимое подтверждение публичного DNS и доступности HTTPS пока не получено. Доступ SSH к серверу ещё не предоставлен.

В зоне `visiooo.ru` создать или исправить запись:

| Тип | Имя | Значение |
| --- | --- | --- |
| A | `@` (корень домена) | `31.192.110.184` |

В REG.RU при использовании DNS-серверов `ns1.reg.ru` и `ns2.reg.ru`: личный кабинет → домен `visiooo.ru` → «DNS-серверы и управление зоной» → «Изменить» → добавить A-запись либо изменить существующую для `@`. В поле адреса указать `31.192.110.184` и сохранить. Если DNS обслуживается другим провайдером или панелью хостинга, запись меняется там; только ради этой операции не переключать NS без проверки всей зоны и почты.

Официальные инструкции: [ресурсные записи в личном кабинете REG.RU](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/nastroyka-resursnykh-zapisey-dns/nastroyka-resursnykh-zapisey-v-lichnom-kabinete), [привязка к IP-адресу](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/rabota-s-dns-serverami/kak-privyazat-domen-k-ip-adresu). Регистратор домена не определяет поставщика хостинга: сведения для политики обработки данных нужно подтвердить отдельно.

Не подставлять IP других проектов, частные или служебные адреса. MX и почтовые TXT не менять. Если для корня есть AAAA, сервер должен действительно обслуживать сайт по соответствующему IPv6; иначе запись нужно исправить после проверки. `www.visiooo.ru` пока не подключается, поскольку канонический адрес выбран без `www`.

## Сервер и сертификат

Развёртывание через GitHub и Docker описано в [SERVER.md](SERVER.md). Приложение доступно только на `127.0.0.1:18080`. `runserver` служит только локальному предпросмотру. Шаблон окружения — `app/.env.production.example`. Заполнить реквизиты оператора, реальные хостинг/почту и SMTP. Не копировать производственные секреты в репозиторий.

До установки проверить существующие virtual host: если `visiooo.ru` уже обслуживает другой проект, сначала определить его назначение и порядок переноса, а не перезаписывать конфигурацию. Порты 80/443 должны быть доступны из интернета, внутренний 18080 — закрыт снаружи.

1. После направления DNS установить отдельный `ops/visiooo-http.conf.example` как `/etc/nginx/conf.d/myqr-platform.conf`, создать `/var/lib/myqr-acme`, проверить `nginx -t` и перечитать Nginx. До сертификата сайт отвечает 503 на обычные запросы, не принимая персональные данные по HTTP.
2. Выпустить сертификат: `certbot certonly --webroot -w /var/lib/myqr-acme -d visiooo.ru --email m@ros100.ru --agree-tos --non-interactive`.
3. Подготовить приложение, применить миграции, собрать статику. Заменить **только собственный** `myqr-platform.conf` содержимым `ops/visiooo-https.conf.example`, проверить пути к сертификату и статику, `nginx -t`, перечитать Nginx. Два примера одновременно не устанавливать. Чужие конфигурации не трогать.
4. Проверить продление сертификата и настроенное расписание Certbot. HTTPS и DNS на текущей машине не устанавливались и фактически не подтверждены.

## Юридические страницы и оплата

- Политика: `https://visiooo.ru/legal/privacy`.
- Оферта: `https://visiooo.ru/legal/offer`.
- Возврат из оплаты: `https://visiooo.ru/app/payments/<идентификатор заказа>` — формируется сервером.
- Адрес уведомлений ЮКассы: `https://visiooo.ru/payments/yookassa/notification`.
- События магазина: `payment.succeeded`, `payment.canceled`, `refund.succeeded`.

Перед рабочим включением пройти `ops/PAYMENTS_AND_LEGAL.md`: магазин, ключ, чеки НПД, фактические сведения оператора и обработчиков. Один выбор домена не включает списания и не подаёт уведомление в Роскомнадзор.

## Проверка после развёртывания

HTTPS без ошибок сертификата; HTTP перенаправляет на HTTPS; главная и документы открываются; чужой Host не попадает в приложение; регистрация и подтверждение почты работают; QR и физический носитель открывают опубликованную визитку; платежи проверены в тестовом магазине, включая уведомление и повторную доставку. Промышленную конфигурацию проверить `python app/manage.py check --deploy --fail-level WARNING`. После проверки включать рабочий магазин отдельно. Проверять не только заполнение конфигурации, но и фактическую доступность домена извне.
