# Почта на сервере visiooo.ru

Подготовлен отдельный Docker Compose проект `visiooo-mail`: Docker Mailserver 17.0.0 (Postfix, Dovecot, OpenDKIM, антиспам), Roundcube 1.7.6 с русским интерфейсом и PostgreSQL для настроек веб-почты. Образы закреплены по версиям. Это конфигурация для установки; фактическая доставка ещё не проверена. Почтовый сервер не запускается обычным `ops/deploy.sh`.

Создаются два аккаунта: `support@visiooo.ru` для обращений и `no-reply@visiooo.ru` для сайта. Веб-почта — `https://mail.visiooo.ru`. Существующий адрес поддержки `m@ros100.ru` на сайте пока сохраняется. Его замена потребует проверки доставки нового ящика.

## 1. Проверки перед установкой

На сервере проверить занятые порты и доступную память:

```bash
ss -ltnp '( sport = :25 or sport = :587 or sport = :993 or sport = :18082 )'
free -h
df -h /var/lib/docker
```

Если SMTP/IMAP уже заняты другой службой, сначала определить её назначение. Не останавливать почту другого проекта. Webmail слушает только `127.0.0.1:18082`; если порт занят, изменить `WEBMAIL_PORT` в `ops/mail/.env` и `proxy_pass` в отдельной конфигурации Nginx. На сервере желательно иметь не менее 2 ГБ доступной памяти под почтовый стек; учесть существующие сайты. ClamAV не включён: антивирусная проверка вложений отдельно не обеспечивается, установлен антиспам SpamAssassin.

Уточнить у ООО «АЙТИБ», разрешён ли исходящий TCP 25 и настраивается ли PTR. Для доставки напрямую на почтовые серверы получателей необходим исходящий 25. Подключение клиентов и сайта на 587 не заменяет исходящий 25. Если провайдер блокирует его, требуется разрешение провайдера либо отдельный согласованный SMTP-релей.

## 2. DNS в REG.RU и PTR у хостинга

Сначала проверить существующие MX/TXT, чтобы сохранить уже работающую почту домена. Новые записи предназначены только для `visiooo.ru`.

| Тип | Имя | Значение |
| --- | --- | --- |
| A | mail | 31.192.110.184 |
| MX | @ | mail.visiooo.ru., приоритет 10 |
| TXT (SPF) | @ | v=spf1 ip4:31.192.110.184 -all |
| TXT (DMARC) | _dmarc | v=DMARC1; p=none |
| TXT (DKIM) | mail._domainkey | Публичный ключ, который будет создан на сервере |

SPF должен быть один на домен. Если он существует, объединить разрешённых отправителей в одной записи, не создавать вторую. `p=none` используется для первого этапа проверки; после проверки SPF/DKIM и всех отправителей выбрать политику DMARC. MX не менять для `ros100.ru`. Не добавлять AAAA до проверки работающего IPv6. PTR для `31.192.110.184` → `mail.visiooo.ru` задаётся хостингом; если сервер уже отправляет почту другого проекта, согласовать общее имя сервера, не менять PTR вслепую.

## 3. Скачать конфигурацию и выпустить сертификат

```bash
cd /opt/visiooo
git pull --ff-only origin main
python3 ops/mail/init.py
mkdir -p /var/lib/myqr-acme
```

Генератор использует системный `openssl`, создаёт случайные пароли, SHA512-CRYPT хеши аккаунтов и файл `ops/mail/.env` с правами 600. При повторном запуске существующие аккаунты и секреты не заменяет. `mail-data/`, секреты и резервные копии исключены из Git и образа приложения. Файл конфигурации `.env` не выполнять через `source`.

Установить отдельный виртуальный хост, если путь назначения не используется другим проектом:

```bash
(
set -e
test ! -e /etc/nginx/conf.d/visiooo-mail.conf
cp ops/mail/http.conf.example /etc/nginx/conf.d/visiooo-mail.conf
nginx -t
systemctl reload nginx
certbot certonly --webroot -w /var/lib/myqr-acme -d mail.visiooo.ru --email m@ros100.ru --agree-tos --non-interactive
)
```

Выполнять последующие шаги только после успешного выпуска сертификата. Команды `test` и копирования выполнять последовательно: при занятом файле не перезаписывать чужую конфигурацию.

## 4. Запуск и DKIM

Открыть входящие TCP 25, 587, 993 в правилах хостинга и локального межсетевого экрана с учётом правил Docker. Порты баз, внутреннюю веб-почту и управляющие сервисы наружу не публиковать. SMTP пересылка требует аутентификации, доверенных Docker сетей нет.

```bash
bash ops/mail/deploy.sh
docker compose --env-file ops/mail/.env -f compose.mail.yaml exec -T mailserver setup config dkim keysize 2048 domain visiooo.ru selector mail
cat mail-data/config/opendkim/keys/visiooo.ru/mail.txt
```

Опубликовать только публичную TXT-запись из `mail.txt` в `mail._domainkey`. Склеить строки значения `p=` без внутренних кавычек и скобок, если REG.RU запрашивает одно текстовое значение. Файлы `mail.private` и пароли никуда не отправлять. Ключ генерировать один раз; повторная генерация меняет подпись и требует обновления DNS.

```bash
docker compose --env-file ops/mail/.env -f compose.mail.yaml up -d --no-deps --force-recreate --wait --wait-timeout 300 mailserver
cp ops/mail/https.conf.example /etc/nginx/conf.d/visiooo-mail.conf
nginx -t && systemctl reload nginx
curl --fail --noproxy '*' -I https://mail.visiooo.ru/
```

Пароль ящика `support@visiooo.ru` хранится в поле `MAILBOX_PASSWORD` файла `ops/mail/.env`; посмотреть его только в своём терминале, не присылать содержимое файла в чат. Пользователь сайта не получает почтовый ящик автоматически. Почта сайта и административный ящик имеют разные пароли. При компрометации пароли нужно менять через средства DMS и синхронно обновлять `.env`.

## 5. Подключить сайт

```bash
python3 ops/mail/connect.py
docker compose --env-file app/.env -f compose.production.yaml up -d --no-deps --force-recreate web
```

Сценарий сначала проверяет TLS-сертификат и SMTP-аутентификацию, затем сохраняет резервную копию `app/.env` в `backups/` и меняет только SMTP-параметры, отправителя и сведения о почтовом сервере в политике. При ошибке TLS/входа настройки сайта не изменяются. Флаги готовности юридических документов и оплаты не включаются.

После подключения зарегистрировать тестовый аккаунт со своим внешним адресом, проверить письмо и восстановление пароля. В веб-почте проверить получение письма с внешнего адреса и ответ. В заголовках полученного с сервера письма проверить SPF, DKIM, DMARC и отсутствие ошибок PTR. Успешный SMTP-вход или внутренняя доставка сами по себе не доказывают доставку во внешние почтовые сервисы. Письма с чеками проверить отдельно после включения платежей.

## 6. Продление, обновления, копии и диагностика

Установить обработчик продления сертификата, если этот путь свободен:

```bash
install -m 0755 ops/mail/renew.sh /etc/letsencrypt/renewal-hooks/deploy/visiooo-mail
certbot renew --dry-run
```

Проверить расписание Certbot и фактическую перезагрузку сертификатов в DMS после первого продления. По мере обновления кода повторно устанавливать обновлённый hook. После генерации DKIM или изменения конфигурации пересоздавать только `mailserver` через `up --force-recreate`: обычный `restart` может пропустить необходимые этапы настройки. Тома с почтой, очередью и ключами сохраняются. Обновления почтовых образов выполнять осознанно после просмотра выпусков и резервирования.

```bash
docker compose --env-file ops/mail/.env -f compose.mail.yaml ps
docker compose --env-file ops/mail/.env -f compose.mail.yaml logs --tail 100 mailserver webmail
docker compose --env-file ops/mail/.env -f compose.mail.yaml exec -T mailserver postqueue -p
```

Резервировать тома `visiooo-mail_mail_data`, `visiooo-mail_mail_state`, базу `visiooo-mail_webmail_database`, каталог `mail-data/config`, файл `ops/mail/.env` и сертификаты с закрытыми ключами. Сохранять шифрованные копии в согласованном расположении, ограничивать доступ. До изменения версии PostgreSQL использовать штатное резервирование/восстановление. `down -v` удаляет данные. Не хранить пароли или письма в GitHub. Страна резервных копий ещё требует подтверждения владельцем.

Почтовый сервис физически размещён на том же сервере, но получатели могут использовать иностранные почтовые системы. До снятия юридического ограничения оценить фактическую передачу персональных данных и при необходимости выполнить процедуру трансграничной передачи. Само размещение SMTP в РФ не подтверждает отсутствие такой передачи.
