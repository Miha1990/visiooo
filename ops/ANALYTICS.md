# Яндекс Метрика

По умолчанию выключена: `YANDEX_METRIKA_ID` не заполнен. Простой просмотр сайта, регистрация и оплата не являются согласием на аналитику. Общая политика — `/legal/privacy`, сведения о cookie — `/legal/cookies`, отдельное согласие — `/legal/analytics`.

## Подключение

1. Создать счётчик для `https://visiooo.ru` в кабинете Метрики. Не включать Вебвизор, рекламные интеграции, менеджер тегов, Advanced Matching, отправку пользовательских данных и автоматические цели. Не добавлять стандартный код счётчика в шаблоны: в нём нет нашего управления согласием.
2. Проверить фактические настройки счётчика и поручение обработки по разделу 5 условий Метрики. Перед запуском учесть цель веб-аналитики, категории технических данных, обработчика и фактическую инфраструктуру в документах и уведомлении Роскомнадзора. Существующее уведомление пользователя находится на рассмотрении: актуальность и необходимость уточнения проверяются в личном кабинете РКН, автоматически сайт его не изменяет.
3. В серверном `app/.env` добавить `YANDEX_METRIKA_ID=НОМЕР_СЧЁТЧИКА` и пересоздать web:

```bash
cd /opt/visiooo
docker compose --env-file app/.env -f compose.production.yaml up -d --no-deps --force-recreate --wait web
```

При изменении номера, редакции или текста согласия сайт запросит новый выбор. Для выключения удалить значение номера и пересоздать web. Номер не является секретом.

## Реализованное поведение

- Аналитика только на `/`, `/pricing`, `/contacts`; в кабинете, админке, формах, документах, примерах и пользовательских визитках отсутствует. Счётчик на собственных доменах не подключается.
- Сначала запрашивается состояние выбора у своего сервера, затем явное согласие. При ошибке получения состояния или записи согласия загрузки счётчика нет. Нет скрытого `noscript`-пикселя, предварительного соединения или загрузки библиотеки до согласия.
- Равнозначные кнопки «Без аналитики» / «Разрешить аналитику», изменение выбора из подвала. Нет согласия по умолчанию, при прокрутке или продолжении просмотра. При отзыве очищаются доступные сайту `_ym*` cookie и локальные записи, страница и другие открытые вкладки перезагружаются. Сторонние cookie на доменах Яндекса удаляются средствами браузера.
- Вебвизор, карта кликов, ссылки, точный показатель отказов, электронная коммерция, менеджер тегов и передача заголовка выключены. Отправляется вручную один просмотр с адресом без параметров запроса/фрагмента и без источника перехода. Идентификаторы аккаунта, почта и содержимое форм не передаются. Функции сбора, включённые отдельно в кабинете Метрики, необходимо согласовывать с описанным режимом.
- Выбор хранится 180 дней в подписанном HttpOnly SameSite=Lax cookie, Secure в промышленной конфигурации. В БД — случайный идентификатор подтверждения, выбор, время, номер счётчика, редакция, точный текст, SHA-256 и предыдущий идентификатор. Нет специальной привязки к аккаунту, почте, IP или User-Agent. Просмотр записей в русской админке: «Пользователи → Согласия и отказы от аналитики»; ручные добавление/редактирование/удаление запрещены.
- Срок подтверждений — до трёх лет для защиты прав. Команда `cleanup_analytics_consents` удаляет старые записи; выполняется при обновлении. Обязательно назначить ежедневный запуск до подключения счётчика.

## Ежедневная очистка

В root `crontab -e` добавить (если сервис размещён в `/opt/visiooo`):

```cron
17 4 * * * cd /opt/visiooo && docker compose --env-file app/.env -f compose.production.yaml exec -T web python manage.py cleanup_analytics_consents >> /var/log/visiooo-analytics-cleanup.log 2>&1
```

Резервные копии и журналы также должны иметь ограниченные сроки хранения по общей политике. Бэкапы нельзя использовать для возобновления отозванной обработки. Сроки хранения отчётов и удаление ранее переданных данных согласуются с возможностями Метрики; отзыв не означает автоматического удаления старых отчётов. Обращения пользователей принимает `support@visiooo.ru`.

## Проверка перед запуском

В новом профиле браузера открыть инструменты разработчика → Сеть и фильтр `yandex`: до выбора и после отказа запросов нет. После разрешения на главной появляется `metrika/tag.js` и запрос просмотра. В «Настройках аналитики» выбрать отказ: после перезагрузки запросов нет. Повторить в кабинете, формах и на визитке — загрузки не должно быть даже при ранее выданном согласии.
